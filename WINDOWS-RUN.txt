JARVIS 3 — Windows setup

1. Install Node.js 24 LTS (24.5 or newer) from https://nodejs.org/.
   Reopen PowerShell after installation. Verify: node --version
2. Download the ZIP from GitHub (Code > Download ZIP, or the version 3 ZIP link).
   Right-click the ZIP and select Extract All.
   The folder may be named JARVIS-main or JARVIS-3.0.0, depending on your download.
   Open that extracted folder until you see package.json, public and server.
   In File Explorer, click the address bar, type powershell.exe, and press Enter.
   PowerShell opens in the correct folder.

   Alternatively, if package.json is at Downloads\JARVIS-main\package.json, run:

   Set-Location "$env:USERPROFILE\Downloads\JARVIS-main"

   Extract All may create an extra outer folder. Always use the folder containing
   package.json, public, and server. There is no separate JARVIS-Windows.zip to find.
3. Create the local server configuration once (do not overwrite an existing .env):

   if (-not (Test-Path .env)) { Copy-Item .env.example .env }
   notepad .env

   In Notepad, set these lines, replacing the placeholder with your own Gemini key:

   GEMINI_API_KEY=YOUR_OWN_GEMINI_API_KEY
   GEMINI_MODEL=gemini-3.1-flash-lite
   HOST=127.0.0.1
   PORT=3000

   Save as .env (not .env.txt). The existing cloud credential is not exported.
   Obtain or manage your own key at https://aistudio.google.com/apikey.
   Keep .env private. It is ignored by Git. Never put the key in public/ files,
   browser code, screenshots, chats, or uploaded archives.
4. No npm install or build is required. In PowerShell:

   npm.cmd run check
   npm.cmd test
   npm.cmd start

   npm.cmd avoids the common PowerShell npm.ps1 execution-policy issue.
   Keep this terminal running. Ctrl+C stops JARVIS.
5. Open http://localhost:3000 in Chrome on this Windows computer.
   You can also launch Chrome's default URL handler with:

   Start-Process "http://localhost:3000"

   Verify configuration (key presence only, not Gemini connectivity):

   Invoke-RestMethod http://localhost:3000/api/status | Select-Object configured, model

   Send a message in the app to test your actual Google credentials and quota.

Voice: Allow the microphone when prompted. Speech input needs a compatible
browser and may use an online browser-vendor speech service. Test voice playback
in Settings. These features have not been tested on your specific Windows device.

Troubleshooting:
- ERR_CONNECTION_REFUSED: ensure npm.cmd start remains running in this folder and
  check its output. Do not double-click index.html; use the HTTP URL above.
- EADDRINUSE: another process uses port 3000. Identify it with
  Get-NetTCPConnection -LocalPort 3000 -State Listen
  Do not kill an unknown process. Change PORT to 3001 in .env, restart JARVIS,
  and open http://localhost:3001 instead.
- Gemini errors: check your key, account access and quota. Cloud-managed secret
  injection does not transfer to Windows. The default model in .env.example is
  account-dependent; the override above worked in the cloud but availability on
  your account still needs a real chat test. Do not disable TLS verification.
- Only loopback access is enabled. No cloud environment settings or router port
  forwarding are required for use on this computer.

GitHub Download ZIP includes the committed project files under JARVIS-main
(or JARVIS-3.0.0 for the version 3 tag archive).
Real credentials and .env are not committed or included. The .env.example file
is a template with an empty API key; create your private .env as described above.

JARVIS tools:
- Select Web search, Research, Debug code or Create image above the chat box.
- Use /search, /research, /debug and /image for explicit routing.
- Attach code/text only after removing passwords, API keys and personal secrets.
- Reminders: review/approve, keep JARVIS open for alerts, or export to calendar.
- Gmail: requires separate Google OAuth setup. Read INTEGRATIONS.md.
- Windows apps: add ENABLE_DESKTOP_TOOLS=true to your local .env and restart.
  Then Tools > Desktop apps. Each launch asks for approval.
- No ChatGPT or Claude API key is needed. Gemini image/search access may have
  separate billing or quota requirements.
- Direct phone control, arbitrary app/screen automation and closed-browser push
  notifications are not implemented. See INTEGRATIONS.md for exact boundaries.

Upgrading an existing installation:
1. Stop the old server with Ctrl+C.
2. Keep your private .env and .data folder; do not upload them to GitHub.
3. Extract the latest GitHub ZIP into a new folder and copy your .env (and .data
   if you want previous generated images/reminders/Gmail access) into it.
4. Review new optional variables in .env.example; never overwrite a working key.
5. Open PowerShell in the new package.json folder and run npm.cmd run check,
   npm.cmd test, then npm.cmd start. Open http://localhost:3000.

JARVIS 3 additions:
- Workflows: build with a prompt or template, select/edit steps, save and publish.
- Open Trigger, recipient & saved notes to configure scheduling and mail recipient.
- Scheduled workflows need the brain terminal/computer to stay running and awake.
- Gmail/Calendar needs your Google OAuth Web client and account consent; reconnect
  older Google connections to grant Calendar read-only access.
- Authority controls automated reads, mail and paired-device actions. Every mail
  and device action still requires approval. Destructive automation is blocked.
- Shared goals & context are explicitly approved server-held information.
- Computers & skills: pair the companion on each computer. Its optional browser
  dependency needs npm.cmd ci and npm.cmd run browser:install in companion/.
  Do NOT copy your Gemini key there. Use the one-time pairing token privately.
- Read WORKFLOWS.md for exact companion setup, safe browser recording, file-root
  restrictions, hosting and what is NOT implemented.
- Natural realtime voice, global Windows recording, arbitrary screen control,
  native phone control and the other product's paid plans are not included.

Additional Command center features:
- AI Core: configure only the model provider you actually use. Keep keys in .env.
- Strict privacy requires local Ollama/llama.cpp and disables browser cloud speech.
- Memory vault: explicitly approve SQLite facts; keyword search is built in.
- Semantic search requires a locally installed Ollama embedding model.
- GitHub: the local app needs its own GITHUB_API_TOKEN for private reads/writes.
- Agent task mode or /task: bounded read-tool loop, with explicit write approval.
- Terminal: npm.cmd run cli (brain must already be running).
- Optional companion Git/Docker/system observations have fixed read-only commands.
- Read CAPABILITIES.md: this is not a Microsoft Store/Google Play app, does not
  include wake-word/offline voice, arbitrary shell or 70+ unrestricted tools.
